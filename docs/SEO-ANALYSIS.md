# SEO-анализ сайта weshow.su

## Что уже хорошо

- **index.html**: единый `title`, `description`, `keywords`, Open Graph, Twitter Card, `lang="ru"`, viewport, theme-color.
- **robots.txt** и **sitemap.xml**: настроены, указан Sitemap, есть блок для Yandex.
- **Верификация**: файл верификации Яндекса в репозитории.
- **Заголовки**: на проверенных страницах один осмысленный `<h1>` (О компании, Портфолио, Услуги и т.д.).
- **Структурированные данные**: в компоненте SEOHead есть JSON-LD Organization (но компонент не используется на страницах).
- **Изображения**: часть картинок с осмысленными `alt` (например, на About).

---

## Критичные проблемы

### 1. Нет постраничного SEO (title, description, OG)

**Проблема:** Компонент `SEOHead` нигде не используется. У всех страниц в выдаче и в соцсетях один и тот же заголовок и описание с главной.

**Влияние:** Плохая релевантность сниппетов, упущенные клики, неинформативные превью при шаринге.

**Решение:** Подключать `SEOHead` на каждой важной странице с уникальными `title`, `description`, `url` (и при необходимости `image`). Для кейсов и услуг — отдельные формулировки под тему страницы.

---

### 2. Нет canonical URL на большинстве страниц

**Проблема:** `rel="canonical"` вручную выставлен только на двух кейсах (CaseSamaraStand, CaseStavropolStandVDNH). Остальные страницы без canonical.

**Влияние:** Риск дублирования при разных вариантах URL (с/без www, с/без слеша, разный порядок параметров).

**Решение:** Добавить в `SEOHead` поддержку пропа `canonical` (или считать из `url`) и выводить `<link rel="canonical" href="...">`. На каждой странице передавать канонический URL.

---

### 3. OG-изображение по умолчанию относительное

**Проблема:** В `SEOHead` по умолчанию `image = '/og-image.jpg'`. Соцсети и мессенджеры требуют абсолютный URL.

**Решение:** По умолчанию использовать `https://weshow.su/...` или собирать абсолютный URL из `url` + путь. При использовании `SEOHead` на страницах передавать `image` только абсолютным URL.

---

## Важные улучшения

### 4. Единый бренд в meta

**Проблема:** В `index.html` — «WESHOW», в дефолтах `SEOHead` — «WeShow NextGen Platform». Разное написание и формулировки.

**Решение:** Везде использовать один бренд (например, «WESHOW») в `title`, `og:site_name`, `author`, JSON-LD.

---

### 5. Динамические страницы без SEO

**Проблема:** Страница кейса по маршруту `/case/:id` (CaseDetail) не задаёт ни title, ни description. При расшаривании отображается главная.

**Решение:** В CaseDetail по данным кейса выставлять `document.title`, meta description и OG (или использовать `SEOHead` с props из `caseData`). Для кейсов с фиксированными маршрутами (`/portfolio/...`) уже можно задать уникальный title/description на каждой странице.

---

### 6. Sitemap: нет lastmod

**Проблема:** В `sitemap.xml` нет тегов `<lastmod>`. Поисковики не видят «свежесть» URL.

**Решение:** Добавить `<lastmod>` в формате ISO 8601 для ключевых страниц. При частом обновлении контента можно генерировать sitemap при сборке с актуальными датами.

---

### 7. Альты у изображений

**Проблема:** Не у всех `<img>` указан осмысленный `alt`. Это важно для доступности и для поиска по картинкам.

**Решение:** Проверить hero-блоки, портфолио, блоки услуг и оборудование — у всех значимых изображений задать короткие описательные `alt`.

---

## Рекомендуемые улучшения

### 8. Breadcrumbs (JSON-LD)

**Проблема:** Нет разметки BreadcrumbList. Для разделов (Услуги → подуслуга, Портфолио → кейс) это улучшило бы сниппет.

**Решение:** Добавлять на внутренние страницы JSON-LD `BreadcrumbList` (главная → раздел → страница) или генерировать через `SEOHead` по переданному массиву пунктов.

### 9. Страница 404

**Проблема:** Нужно убедиться, что 404 отдаёт код 200 для SPA только для HTML, а для роботов не создаёт путаницы. Заголовок страницы лучше сделать уникальным («Страница не найдена — WESHOW»).

**Решение:** В компоненте 404 задать отдельный title и при желании `robots: noindex, follow`, чтобы не индексировать саму страницу 404.

### 10. Технические и игровые страницы

**Проблема:** Страницы вроде `/tetris`, `/game`, `/test-header` не должны попадать в поиск как основные.

**Решение:** Они не в sitemap — ок. При необходимости на таких страницах выставлять `meta name="robots" content="noindex, follow"` (через отдельный компонент или условие в layout).

## Что ещё можно сделать (опционально)

### SEO и разметка

- **FAQ (JSON-LD)** — на странице «Технологичные выставочные стенды» есть блок FAQ; можно добавить разметку `FAQPage` (schema.org), чтобы вопросы могли попадать в расширенные сниппеты в поиске.
- **Breadcrumbs на всех внутренних** — сейчас хлебные крошки стоят на части страниц (о компании, контакты, мультимедийный контент, кинетический экран, один кейс). При желании можно добавить `breadcrumbs` во все подстраницы услуг, оборудования и кейсов.
- **LocalBusiness / Place** — если важен поиск «рядом» и карты, можно расширить JSON-LD: добавить тип `LocalBusiness` или `Place` с адресом и координатами (сейчас в Organization есть только ContactPoint).
- **Специальные OG для кейсов** — для расшаривания кейсов можно задавать отдельное `image` в SEOHead (например, обложка кейса), чтобы в соцсетях было релевантное превью.

### Техника и доступность

- **Ссылка «Перейти к контенту»** — для клавиатурной навигации и скринридеров: одна ссылка в начале страницы с `href="#main"` и `id="main"` на `<main>`, скрытая визуально до фокуса.
- **Размеры изображений** — у важных картинок (hero, портфолио) указать `width` и `height` (или aspect-ratio), чтобы уменьшить сдвиг контента (CLS) при загрузке.
- **Яндекс.Метрика / аналитика** — подключение счётчика в `index.html` или через тег-менеджер для анализа трафика и поведения (не меняет SEO напрямую, но нужно для решений по контенту).

### Контент и структура

- **Единый адрес в canonical** — если сайт доступен и по `www.weshow.su`, в Вебмастере задать предпочтительный зеркал (например, без www) и при необходимости редирект; canonical уже везде без www.
- **Обновление lastmod** — при следующих правках страниц можно обновлять даты в `sitemap.xml` вручную или генерировать sitemap при сборке (скрипт по датам файлов/коммитов).
- **Блог / кейсы в виде статей** — если появятся разделы с регулярными статьями, для них имеет смысл разметка `Article` (JSON-LD) и отдельные OG (type `article`, дата публикации).

### Не обязательно для SEO

- **CSP, referrer policy** — при желании усилить безопасность через заголовки или meta (влияет на безопасность, не на ранжирование).
- **Отдельная страница для людей** — если нужна явная «карточка» компании для поиска (адрес, часы, услуги), можно оформить одну страницу «Для партнёров» или «Контакты» с полной разметкой LocalBusiness и ссылкой из футера.
